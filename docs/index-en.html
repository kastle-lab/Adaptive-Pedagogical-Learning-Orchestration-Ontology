Ontology Specification

The Adaptive Pedagogical Learning Orchestration (APLO) Ontology is a modular RDF/OWL vocabulary for representing dependencies among pedagogical structure, learning objectives, learner context, assessment evidence, feedback, and temporally situated learner-awareness observations in adaptive educational systems.

APLO does not define a tutoring algorithm or adaptation policy. Instead, it provides the semantic structures required to relate instructional configurations to learner situations and evaluation evidence. The ontology comprises four interoperable modules and has been subjected to structural checks, synthetic-data materialization, and competency-question validation; these checks assess representational coverage rather than educational efficacy.

Purpose and scope

APLO extends curriculum-centered knowledge representation with a process-aware representation of adaptive instruction. Curriculum resources and skill structures alone do not express instructional ordering, the relationship between an evaluation result and a learning objective, response provenance, or changes in learner awareness. APLO provides explicit RDF/OWL relations for representing those dependencies.

APLO was developed through a competency-question-driven application of Modular Ontology Modeling (MOMo) and reusable ontology design patterns. Its intended application context includes neurosymbolic educational agents; however, APLO neither implements an agent nor entails a recommendation for the next instructional action.

The stable term namespace is https://kastle-lab.org/aplo/lod/ontology#, conventionally abbreviated aplo-ont:. The ontology IRI (without the hash) is https://kastle-lab.org/aplo/lod/ontology. Learning resources and curriculum-facing concepts may be represented using distinct external vocabulary terms.

See the APLO repository for the authoritative OWL source, schema visualizations, competency questions, mappings, and synthetic validation material.

Modular overview and navigation

The four modules connect through interface notions such as LearningObjective, LearningSituation, PedagogicalTechnique, AwarenessObservation, Topic, and Skill. The aggregate ontology is represented in the repository as the full-schema OWL file.

Ontology design

APLO is organized into four modules: pedagogical framework, learning objective, learner evaluation, and learner model. Each module models one concern of adaptive learning; shared terms connect the modules without introducing a single, overly broad orchestration class.

Pedagogical technique and framework

This module describes how instruction is organized. A pedagogical framework contains pedagogical elements, which can be ordered when sequence matters. Pedagogical techniques are the methods used in instruction, while pedagogical objectives describe their intended effects, such as recall, engagement, or knowledge transfer.

Learning objective

This module connects an intended learner outcome to the instructional context. A learning strategy combines learning objectives with pedagogical techniques. Learning objectives can also be related to learner situations and curriculum-facing resources, linking what is to be learned with how and when it is taught.

Learner evaluation

This module records how learning is assessed and what follows from an assessment. An assessment exercise uses an evaluation technique and metric to produce a result. Feedback and other responses can be linked to their source and time, making the origin and interpretation of evaluation evidence explicit.

Learner model

This module represents learner-specific context: goals, preferences, challenges, situations, and skills. It records awareness as an observation about a topic or skill, with an assigned level and optional time reference. Multiple observations can therefore represent changes in awareness over time.

Reuse, alignment, and imports

APLO references curriculum-facing concepts from CurrKG and is conceptually aligned with learner-profile ontologies such as EduCOR. The aggregate OWL file uses external edu-ont: identifiers for some curriculum-facing classes. These references are not, by themselves, owl:imports or owl:equivalentClass axioms.

Evaluation and limitations

Validation included iterative OOPS! structural checking, 22 synthetic input files, Foundry materialization of 6,836 RDF triples, and query validation of 94 competency questions in Apache Jena Fuseki. All competency questions were supported by the synthetic test data. These artifact-level checks assess representational fitness; they do not establish improved learning outcomes, and APLO does not encode a policy for selecting the next pedagogical action.
